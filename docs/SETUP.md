# Live installation guide

**For the existing Social Sync app on Render:** use [START-HERE.md](../START-HERE.md)
to publish the missing theme block to your existing Shopify app. You do not need
to create another Shopify or Meta app. The guide below covers a fresh installation.

This release targets your own single store. The local demo requires no accounts. Production requires the account-owned setup below; none of it has already been performed for you.

## 1. Register the Shopify app

Use the [Shopify Dev Dashboard](https://dev.shopify.com/dashboard) to create an app and choose the distribution appropriate to your own store. You need permission to develop/install apps on that store. Do not submit this initial release to the App Store as a multi-store SaaS app.

Keep the app’s Client ID and Client Secret private. Use your actual `something.myshopify.com` store domain, even if your storefront uses a custom domain.

Update `shopify.app.toml`:

- `client_id`: your app Client ID.
- `application_url`: your hosted app’s HTTPS origin, such as `https://social.your-domain.com`.
- `auth.redirect_urls`: that origin followed by `/auth/shopify/callback`.
- Keep `embedded = false` for this standalone app.
- Keep `write_app_proxy` as the only Shopify access scope. Product/order/customer access is not needed.
- Keep the `/proxy` app proxy destination and the webhook routes as provided.

Install Shopify CLI on your development computer:

```sh
npm install -g @shopify/cli@latest
shopify app config validate --json
shopify app deploy
```

Run the latter commands from this app directory. Follow Shopify’s account sign-in when prompted. Keep the supplied configuration when linking the app; if the CLI creates a named configuration, copy the relevant URL, proxy and webhook settings into it and validate that configuration before deployment. Retain any extension `uid` generated by Shopify in `extensions/social-gallery/shopify.extension.toml` for subsequent releases.

`shopify app deploy` publishes configuration and extensions. It **does not host the Node server**. The server must be deployed separately in step 3.

This environment could not complete CLI authentication, so a successful authenticated config validation and extension deployment remain required.

## 2. Register and configure the Meta app

Use [Meta for Developers](https://developers.facebook.com/apps/). Configure the Facebook Login flow for business accounts and the Instagram API **with Facebook Login**. This implementation does not use Instagram Login’s `instagram_business_*` permission flow.

Connect the store’s Instagram Business or Creator account to the Facebook Page you manage. The app chooses the linked Instagram account automatically after Page selection.

Configure the following URLs using your live app origin:

| Meta setting | URL path |
| --- | --- |
| Valid OAuth redirect URI | `/auth/meta/callback` |
| Privacy policy | `/privacy` |
| Data deletion callback | `/meta/delete` |
| Deauthorization callback | `/meta/deauthorize` |

The login flow requests these permissions:

| Permission | Purpose |
| --- | --- |
| `pages_show_list` | Choose a Page the merchant manages. |
| `pages_read_engagement` | Read accessible Page content. |
| `pages_read_user_content` | Read accessible visitor posts and comments. |
| `instagram_basic` | Identify the linked Instagram account and read eligible media/tags. |
| `instagram_manage_comments` | Read accessible comments on its media. |

Meta decides which permissions and use cases are available or approved. App role/test-account access during development does not prove production access. Complete any App Review, business verification, privacy or use-case requirements shown in your Meta dashboard before opening production access. In particular, verify that the requested user-content access is approved for your intended storefront-display use case; approval cannot be guaranteed by this app.

The implementation defaults to Graph API `v24.0`; select a supported version for your registered app and run the live acceptance checks before changing it. It imports only what the authorized API returns and never scrapes profiles.

Facebook Login configurations vary by app type. By default, the app sends a standard `scope` list to the OAuth dialog. If your Meta app requires Facebook Login for Business, put its configuration ID in `META_LOGIN_CONFIG_ID`. The app will send `config_id` instead of the scope list; enable the permissions above in that Meta configuration and choose a user-token login flow. Verify that Page enumeration and both social sources work under the resulting permissions before launch.

## 3. Host the server

Use a host that runs **one long-lived Node.js 24 process** behind HTTPS, with a persistent volume. Polling runs inside that process. App hosting charges are separate from Shopify.

Copy `.env.example` to a private `.env` and fill in:

- `APP_URL`: the same HTTPS origin used in Shopify and Meta redirects.
- `SHOP_DOMAIN`: your allowlisted `.myshopify.com` domain.
- `SHOPIFY_API_KEY` and `SHOPIFY_API_SECRET`.
- `META_APP_ID` and `META_APP_SECRET`.
- `SUPPORT_EMAIL`: the store’s contact for content removal/privacy requests.
- `ENCRYPTION_KEY`: a new random 32-byte key represented as 64 hex characters.

Generate an encryption key locally:

```sh
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Save it in your secret manager. Keep it stable across redeploys. Changing it without migration makes existing encrypted connections unreadable and requires reconnecting accounts.

For Docker on an existing server:

```sh
docker compose up -d --build
```

The included compose file binds port 3000 to the server’s loopback address. Put your existing HTTPS reverse proxy in front of it and forward to `127.0.0.1:3000`. Preserve request bodies and Shopify/Meta signature headers. Configure reasonable proxy request limits and do not log OAuth callback query strings or authorization headers.

Alternatively run `npm start` with the same environment variables and a persistent `DATA_DIR`. Keep `NODE_ENV=production`; never enable `DEMO_MODE` on a live host. The app fails closed if live Shopify configuration or encryption is absent.

Visit `/health` to check the process. Back up the SQLite database using a SQLite-consistent backup method; protect the database and encryption key separately. Apply your retention/deletion policy to backups too. Review the included privacy notice against the actual hosting and backup practices before launch.

## 4. Install and connect

1. Use Shopify’s installation link for your app/store. Open the app to complete Shopify authorization.
2. In **Connections & settings**, choose **Connect with Facebook**.
3. Authorize the relevant Page and Instagram permissions.
4. Choose the intended Facebook Page. Switching Pages erases the previously imported social dataset.
5. Wait for the first sync and inspect **Sync activity**. Reconnect if access has expired; inspect Meta permissions if a source cannot be read.
6. Confirm whether automatic publishing or review-first mode fits your display process. The default is automatic, as requested.

## 5. Add the website gallery

In your Shopify theme editor, open the page/template where you want the gallery. Choose **Add block → Apps → Social gallery**, configure it and save. The theme must support app blocks. Your existing theme code is not edited by this package.

You can change:

- Heading and desktop columns.
- Instagram, Facebook or both.
- Maximum items shown.
- Whether to match the current product page.
- App proxy path, if you customized it in Shopify.

For product matching, enter the handle from a product’s `/products/your-product-handle` URL on each gallery item. Enable **Match current product** in the block. An unassigned item will not appear in a product-filtered gallery.

The public storefront only receives published, available, recently verified, non-demo items. Visitors never receive account tokens, session tokens, pending content or hidden content from the feed endpoint. Empty/error galleries collapse on the live storefront, while the theme editor shows an explanatory message.

## 6. Before launch

Run every live acceptance check in `VALIDATION.md`. In particular, make a real tagged post/comment, verify it appears after a sync, hide it, and verify it disappears from the storefront. Then remove the original source content and check reconciliation. Do not claim universal capture or instant synchronization: the first version’s discovery limits are listed in `README.md`.
